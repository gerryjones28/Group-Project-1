1. WHAT THIS ASSIGNMENT IS
================================================================================

This is a script setup for a college scorecard dataset that we will do EDA/regression analysis on. I'll be working with three partners, one of which setup the Github repo for us.

Source: "Group Project I - The College Scorecard Dataset" (Docs/Group Project I.pdf).

Premise (from the brief):
  The U.S. Department of Education collects information for public and private
  colleges/universities and assembles it into public "scorecards". The data
  measures affordability and ease of access to student outcomes post-graduation,
  and "can be summarized to highlight schools providing the best value in
  education."

Key facts stated in the brief:
  - Data are available in yearly reports from 1996 through 2023 (the files we
    actually have run 1996-97 through 2025-26 - see section 6).
  - Each year has roughly 7,000 observations (colleges) and 2,000-3,300 variables.
  - For privacy reasons some data are masked as "PrivacySuppressed".
  - Some values are collected as two-year moving averages to reduce variability.
  - For encoded variables, values are translated in
    CollegeScorecardDataDictionary (an .xlsx in our copy, see section 6).

Links given in the brief:
  Website:        https://collegescorecard.ed.gov/
  Dataset:        https://collegescorecard.ed.gov/data        (also on Canvas)
  Documentation:  https://collegescorecard.ed.gov/data/data-documentation
  Glossary:       https://collegescorecard.ed.gov/data/glossary  (also on Canvas)
  API helper pkg: https://github.com/RTICWDT/college-scorecard

THE FOUR GOALS (verbatim - this is the deliverable structure)
--------------------------------------------------------------------------------
1. Read the data into a language-native format. This may involve:
   a. Either aggregating yearly files in R, or
   b. Using an interface between R and a native database format, or
   c. Accessing the API described in Documentation above, and at
   d. https://github.com/RTICWDT/college-scorecard
   e. Properly treating NAs and other encoded variables

2. Assess the quality of the data. This may include:
   a. Measuring fractions of missing values, and/or relationships in missingness
      between variables of interest
   b. Calculating numeric quality scores for several metrics

3. Recode any variables of interest. For example:
   a. Create combined categories from several columns
   b. Aggregate summary statistics from factor levels between columns
   c. Normalize data between categories, or treat separate categories
      separately, as appropriate

4. Identify and display any relationships of interest.
   a. Ideally, these will use some of the recoded variables above, consider
      effects of data quality, and answer a series of defined questions.
   b. Outcomes might cover access, affordability, student outcomes, or other
      categories.

Note the phrase "answer a series of defined questions" in 4a. That is what turns
an EDA into an argument, and it is the piece that has NOT been done yet.

00 is shared and sourced by the other three.

  00_common.R  (443 lines)  NOT run directly. Contains:

         var SC_PROJECT_ROOT)
       - path constants: DATA_DIR, DICT_XLSX, SIMPLIFIED_DIR, REPORTS_DIR,
         FIGURES_DIR, INST_LATEST, FOS_LATEST

         inside some label text)
       - chunked CSV auditing helpers, fnum()/pct1() formatters, md_table()

       - recode helpers: control/level/region/preddeg/highest-degree/carnegie

11. TRAPS THAT WILL BITE A GOAL-4 ANALYSIS
================================================================================

 1. THE PANEL IS ONE ROW PER INSTITUTION PER SOURCE FILE. 208,759 rows for
    ~6,300-7,700 institutions. UNITID is the only reliable join key and is NOT
    deduplicated. Any count or aggregate that forgets this is wrong by ~30x.

 2. SELECTION IS CORRELATED WITH EVERYTHING YOU WOULD MEASURE. Completeness vs
    log(enrolment) = 0.64; only 23.7% of institutions have all ten headline
    metrics. Any model on the headline metrics silently over-represents large
    public 4-year institutions. Report dq_tier / pct_headline_complete alongside
    EVERY result.

 3. STRUCTURAL CEILINGS ARE NOT GAPS. 44 of the 113 core variables never reach
    80% coverage in ANY year. Do not impute; do not silently drop. Declare the
    denominator for every statistic.

 4. "PS" AND "NA" MEAN DIFFERENT THINGS.
      NA = not collected / not applicable / not available.
      PS = "PrivacySuppressed": collected but withheld because the group was too
           small to publish.
    PS carries information (small cohort size); NA does not.
    n_headline_privacy_suppressed and mean_privacy_suppressed already count PS.
    Treat them differently in the write-up.

 5. THE 7,020 TEXT-"NA" UNITIDs. In the field-of-study file, 7,020 program rows
    (778 institutions, mostly foreign or closed - e.g. "Aarhus University", plus
    a few US schools like "Judson College") carry the literal TEXT "NA" in the
    UNITID column. Scorecard publishes their programs but no institution-level
    ID, so they can NEVER be joined to the institution file. Filter on the
    has_unitid flag before joining or aggregating.
    (The earlier, misleading name for this flag was is_institution_row.)

 6. TWO-YEAR MOVING AVERAGES. The brief warns that some values are 2-year rolling
    means (e.g. C150_4_POOLED, RET_FT4_POOLED, RPY_3YR_RT). This induces
    autocorrelation and blunts single-year shocks. Do not over-read one-year
    moves.

 7. MISSINGNESS CLUSTERS. PCTPELL and PCTFLOAN have Jaccard 1.00 - they are the
    SAME 828 institutions. Treating them as two independent predictors is a
    statistical mistake.

 8. NET PRICE ABOVE STICKER IS NOT A BUG. See section 8. 19.5% of institutions
    trip that check legitimately. Only the 12 negative net prices and 11
    zero-enrolment rows are genuine errors (0.2% each).

 9. rscorecard / API: each member needs their OWN DATAGOV_API_KEY, in the HOME
    .Renviron, never hard-coded in a .R script, never in the repo.

15. GLOSSARY OF THE SHORTHAND USED HERE
================================================================================

  Scorecard      the College Scorecard dataset (US Dept of Education).
  UNITID         the institution ID. The primary join key. Can also appear as the
                 literal text "NA" (see trap 5).
  MERGED####_##  the yearly institution-level files, 1996_97 ... 2025_26 (30 of
                 them). One row per institution per year, 3,308 columns.
  FoS            Field of Study - one row per institution x CIP program. Only

                 cip2 = the 2-digit program family.

                 measure, and the one with the best historical coverage.

  C200_4         200%-of-expected-time completion rate.
  GRAD_DEBT_MDN  median federal debt of graduates.
  MD_EARN_WNE_P10   median earnings, working and not enrolled, 10 years after
                 entry. The earnings headline measure.
  RPY_3YR_RT     3-year cohort repayment rate.
  PS             "PrivacySuppressed" - collected but withheld (group too small).
  NA             not collected / not applicable / not available.
  DQ / dq_tier   data quality.
  Jaccard        both-missing / either-missing. 1.00 means they go missing
                 together, i.e. they are not independent.
  headline       the TEN metrics the group is most likely to model on: ADM_RATE,
                 UGDS, TUITIONFEE_IN, net_price, PCTPELL, PCTFLOAN, grad_rate,
                 RET_FT4, earn_p10, grad_debt_mdn.
